# Why Learn Programming When AI Can Write Code?

## Working Argument

AI may reduce the need for designers to write code from scratch, but this does not make understanding programming irrelevant. For designers, the purpose of learning programming is shifting away from competing with machines at writing syntax. Instead, designers need enough computational knowledge to read, evaluate, modify, and direct the systems that increasingly produce code for them.

## Ideas to Develop

### Reading may become more important than writing

AI can already generate working code quickly, but working code is not necessarily good code. Someone still needs to identify mistakes, understand what can be optimized, and judge whether the result actually matches the intended design.

### Understanding the medium

Designers do not necessarily need to become professional programmers. However, if computation is part of the medium they work with, they should understand how that medium behaves. This becomes especially important in technical art, interactive design, and generative systems.

### A solution is not the same as understanding

AI makes answers much easier to obtain. For beginners, this can create a temptation to copy a working solution without understanding why it works. The result may solve the immediate problem while leaving the learner unable to solve the next one independently.

# Why Learn Programming When AI Can Write Code?

AI can now generate working code from ordinary language in seconds. For a beginner, this raises an obvious question: if a machine can increasingly perform the task of writing code, why should a designer still spend time learning programming?

I do not think designers in 2026 need to learn programming for exactly the same reason they did ten years ago. The ability to write every line of code from memory may become less important. However, this does not make programming knowledge irrelevant. Instead, I think its value is shifting from writing code toward understanding computational systems well enough to read, evaluate, modify, and direct what machines produce.

## Reading May Matter More Than Writing

AI can generate code quickly, but code that runs is not automatically good code. It may contain unnecessary complexity, inefficient logic, incorrect assumptions, or simply produce something different from what the designer actually intended.

This became clear to me while learning technical art. Tutorials and AI tools can often tell me which node to connect or which parameter to change in Unreal Engine. That can solve an immediate problem very quickly. However, when the result behaves incorrectly, knowing only the answer is not enough. I still need to understand what the parameters are doing, how different parts of the system influence each other, and where the problem might actually come from.

For this reason, I think reading and judging code may eventually become more important for many designers than writing it completely from scratch. If AI writes the first version, someone still needs enough knowledge to decide whether that version is useful.

## Programming as Understanding a Medium

A designer does not need to become a professional software engineer simply because they work with digital tools. However, understanding the basic logic of a medium gives the designer more control over it.

My background is primarily in illustration, where I am usually responsible for deciding what the final image looks like. Technical art changed the way I think about this. When creating an effect such as fire in Unreal Engine, I am not simply drawing the appearance of a flame. I am working with relationships between velocity, noise, temperature, dissipation, randomness, timing, and other variables. The final image emerges from the rules connecting those variables.

Programming therefore introduces a different kind of design thinking. Instead of only designing an image, I can design a system that produces behavior. Understanding that system makes it possible not only to follow its intended use, but also to modify or creatively misuse it.

## A Solution Is Not the Same as Understanding

At the same time, AI creates a new problem for beginners: it makes solutions extremely easy to obtain.

Without AI, learning often involves encountering a problem, searching for information, trying something, failing, debugging it, and gradually understanding why it works. With AI, that process can sometimes become: ask a question, receive an answer, copy it, and move on.

The second process is obviously faster, and I do not think efficiency itself is a bad thing. The danger is that a working result can create the illusion of understanding. I have experienced this while learning technical tools: AI can tell me exactly what to click, but if I only follow the instructions, I may be unable to solve a slightly different problem later.

This means that learning programming alongside AI requires a different kind of discipline. The goal should not be to avoid AI, but to use its answers as material to question, test, and understand.
